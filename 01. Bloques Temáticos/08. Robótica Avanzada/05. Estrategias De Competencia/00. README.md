## Propósito del módulo

Ganar un combate no depende de tener el mejor robot, sino de entender el reglamento, saber qué hace el rival y ajustar el robot a lo que la competencia realmente premia. Este módulo cierra el bloque con esa mirada: analizar el reglamento antes de competir, aprender a revisar lo que pasó después de cada combate, construir una estrategia concreta para el CenfoBot, y optimizar tanto el hardware como el software con base en lo que se observó.

Al finalizar, los estudiantes podrán leer un reglamento y sacar de él decisiones de diseño, analizar un combate con criterio y no solo con impresiones, y justificar cada cambio en el robot con una razón de competencia. Los recursos están organizados en archivos numerados para mantener el flujo de aprendizaje propuesto.

## Conceptos clave del módulo

**Análisis posterior a la competencia.** Un combate que no se revisa se repite igual la próxima vez. Analizar es separar lo que falló por el robot, lo que falló por la estrategia y lo que falló por el rival, y decidir qué se corrige primero.

**Lectura del reglamento.** El reglamento define el campo de juego: tamaño del dojo, tiempo de combate, qué cuenta como salida, qué piezas están permitidas. Cada una de esas reglas abre o cierra una decisión de diseño.

**Estrategia de combate.** Una estrategia es una secuencia de decisiones: qué hacer al arrancar, cómo buscar al rival, cómo empujar y cómo reaccionar si el robot queda en el borde. No es un solo movimiento, es un plan con alternativas.

**Optimización de hardware y software.** El hardware define lo que el robot puede hacer (tracción, peso, sensores); el software define qué tan rápido y qué tan bien lo hace. Optimizar es mejorar ambos con evidencia, no por intuición.
