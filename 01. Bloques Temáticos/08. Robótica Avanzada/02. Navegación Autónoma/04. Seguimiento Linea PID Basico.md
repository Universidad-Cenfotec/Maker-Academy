## Descripción

El seguimiento de línea permite estudiar cómo un sistema de control convierte una medición en correcciones sucesivas. Esta lección aplica el concepto de error y la respuesta proporcional presentados en [Control Proporcional](../01.%20Control%20De%20Precisión/02.%20Control%20Proporcional.md), y explica qué agregan los términos integral y derivativo.

## Propósito

Distinguir la medición de la línea, el error de seguimiento y la salida del controlador; comprender los términos P, I y D y reconocer las condiciones de hardware que requiere esta aplicación.

## Contenido

### De la referencia a la corrección

Un seguidor compara la posición de una línea con la posición deseada bajo el robot. La diferencia es el error. Con una matriz de varios sensores distribuidos transversalmente, se puede estimar si la línea está a la izquierda, centrada o a la derecha y cuánto se ha desplazado.

Una regla binaria («gira a la izquierda» o «gira a la derecha») usa poca información y puede resultar brusca. Un controlador usa el error medido para graduar la corrección. La idea de variar la respuesta según el error se presentó en el tema proporcional; aquí se aplica a una tarea concreta.

### Qué significa PID

En un controlador discreto, una forma introductoria de escribir la salida es:

```text
u = Kp * error + Ki * integral(error) + Kd * derivada(error)
```

- **P (proporcional):** responde al error actual.
- **I (integral):** acumula el error a lo largo del tiempo; puede compensar un sesgo persistente, pero una acumulación excesiva puede saturar la salida.
- **D (derivativo):** responde a la rapidez de cambio del error y puede amortiguar la respuesta. No predice literalmente el futuro y puede amplificar ruido de medición.

En un cálculo discreto, la integral suele acumular `error * dt` y la derivada estima `(error_actual - error_anterior) / dt`. Por eso `dt` debe corresponder al tiempo entre lecturas, no a un valor arbitrario. La salida se transforma en diferencias de potencia entre ruedas y se limita al rango admitido.

### El sensor importa tanto como el controlador

El kit documentado del Sumobot/CenfoBot incluye cuatro sensores infrarrojos ubicados en las esquinas para reconocer el borde blanco del dojo; no documenta una barra lineal de sensores bajo el centro para seguir una pista. Esos sensores se pueden usar para tratar el **borde de combate** como una referencia de seguridad, pero no se deben describir como un arreglo dedicado a seguimiento de línea.

El seguimiento de una línea es un concepto transferible. Para una implementación directa se necesitaría un arreglo de sensores apropiado, una configuración alternativa de sensores o un simulador. Si se propone como hipótesis de extensión del CenfoBot, hay que especificar el hardware requerido y calibrar sus lecturas en la superficie real.

### De las lecturas al error

Con un arreglo transversal, cada sensor aporta una señal calibrada. Puede asignarse un peso según su posición y estimarse la ubicación de la línea mediante un promedio ponderado. El error depende de la convención de signos y de si la pista es clara sobre fondo oscuro o al revés; no hay un umbral universal.

Si ningún sensor detecta la línea, el error deja de estar definido por esa lectura. El sistema necesita una política de pérdida de línea (por ejemplo, detenerse o buscar con una estrategia limitada); no debe seguir aplicando como si la medición fuera válida.

### Ejemplo conceptual en tres representaciones

Estos fragmentos muestran el ciclo de control, no son programas listos para conectar a los sensores del kit. `leer_error_linea()` supone un arreglo lineal calibrado; `mover_diferencial()` representa la interfaz de motores de la plataforma elegida.

#### CircuitPython

```python
error = leer_error_linea()  # requiere arreglo lineal calibrado
integral += error * dt
derivada = (error - error_anterior) / dt
u = KP * error + KI * integral + KD * derivada
mover_diferencial(limitar(base + u), limitar(base - u))
error_anterior = error
```

#### C++ / Arduino

```cpp
float integral = integralAnterior + error * dt;
float derivada = (error - errorAnterior) / dt;
float u = KP * error + KI * integral + KD * derivada;
moverDiferencial(limitar(base + u), limitar(base - u));
errorAnterior = error;
integralAnterior = integral;
```

#### Bloques de IdeaScratch

```text
leer el error estimado del arreglo de sensores
acumular (error * dt) en integral
calcular derivada: (error - error_anterior) / dt
calcular u: (Kp * error) + (Ki * integral) + (Kd * derivada)
limitar y distribuir (base + u) y (base - u) entre las ruedas
actualizar error_anterior
```

Los tres describen la misma secuencia matemática. Los nombres exactos de las funciones y los bloques dependen de la plataforma; la implementación requiere comprobar pines, escala de lectura, orientación de motores y periodo real de muestreo.

### Cómo leer el comportamiento

Al analizar una respuesta, primero revise el signo y la calidad de la medición. Luego observe si la corrección es insuficiente, oscilatoria o se satura. La velocidad base y las ganancias interactúan: cambiar la velocidad puede exigir volver a evaluar el controlador. Las ganancias no se copian entre robots, pistas ni arreglos de sensores sin validación.

Un P sencillo permite estudiar la relación directa entre error y salida; D puede amortiguar cambios bruscos, y el término I se agrega solo si hay una razón para corregir un sesgo sostenido. Ajustar valores y recorrer una pista corresponde a las prácticas guiadas futuras.

### Relación con la navegación del Sumobot

El Sumobot puede demostrar control con el giroscopio, lectura de infrarrojos para protegerse del borde, detección frontal con ultrasonido y comportamientos de búsqueda/avance. Seguir una línea es otra tarea: sirve para comparar una referencia de piso con la orientación del robot, pero requiere aclarar la disposición de sensores y la pista. Los conceptos de control se transfieren; el hardware de una aplicación no se debe dar por supuesto en la otra.
