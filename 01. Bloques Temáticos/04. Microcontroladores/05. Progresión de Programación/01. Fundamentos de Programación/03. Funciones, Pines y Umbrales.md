Explica, desde cero, cómo organizar código en funciones, qué es un pin y cómo se declara, y qué es un umbral y cómo se define, cerrando así el vocabulario básico necesario para programar cualquier sensor o actuador.

## Propósito

Con variables, condicionales y bucles ya cubiertos, quedan tres piezas para poder leer cualquier tutorial de sensores sin quedarse con dudas: **funciones** (para no repetir código), **pines** (para saber por dónde entra y sale la información) y **umbrales** (para decidir en qué momento un valor cuenta como "mucho" o "poco").

## Funciones: agrupar código que se repite

Una función es un bloque de código con un nombre, que se puede "llamar" (ejecutar) cada vez que se necesite, en vez de volver a escribirlo.

```cpp
void encenderAlarma() {
  digitalWrite(PIN_BUZZER, HIGH);   // encendemos el buzzer
  delay(500);                        // lo dejamos sonando medio segundo
  digitalWrite(PIN_BUZZER, LOW);    // lo apagamos
}

void loop() {
  if (distancia < UMBRAL_CM) {
    encenderAlarma();   // en vez de repetir las 3 líneas, llamamos a la función por su nombre
  }
}
```

Toda placa Arduino ya usa dos funciones especiales sin que el docente las tenga que crear:
- `setup()`: se ejecuta **una sola vez**, al encender la placa. Aquí se configuran los pines.
- `loop()`: se ejecuta **en bucle, para siempre**, mientras la placa esté encendida.

En Python (MicroPython, CircuitPython), una función se declara con `def`:

```python
def encender_alarma():
    buzzer.write_digital(1)   # encendemos el buzzer
    sleep(500)                 # lo dejamos sonando medio segundo
    buzzer.write_digital(0)   # lo apagamos

while True:
    if distancia < umbral_cm:
        encender_alarma()   # llamamos a la función por su nombre
```

### Funciones con parámetros

Una función puede recibir información para trabajar con ella, en vez de repetir una función distinta para cada caso:

```cpp
void parpadear(int pin, int veces) {
  // "pin" y "veces" son los parámetros: cambian cada vez que se llama a la función
  for (int i = 0; i < veces; i++) {
    digitalWrite(pin, HIGH);
    delay(200);
    digitalWrite(pin, LOW);
    delay(200);
  }
}

void loop() {
  parpadear(PIN_LED_ROJO, 3);    // hace parpadear el LED rojo 3 veces
  parpadear(PIN_LED_VERDE, 5);   // hace parpadear el LED verde 5 veces
}
```

> **Nota para docentes:** un parámetro es exactamente lo mismo que una variable, pero su valor lo define quien llama a la función en ese momento, no quien la escribió.

## Pines: cómo entra y sale la información

Un pin es cada uno de los puntos metálicos en el borde de una placa por donde se conecta un cable. Es la puerta de entrada o salida entre el programa y el mundo físico.

<img width="600" alt="Arduino UNO R3: placa con microcontrolador, 14 pines digitales, 6 pines analógicos, conector USB tipo B y conector de alimentación" src="https://upload.wikimedia.org/wikipedia/commons/3/38/Arduino_Uno_-_R3.jpg" />

Hay dos tipos de pines, y cada uno se declara distinto en el código:

| Tipo de pin | ¿Qué señal maneja? | ¿Para qué se usa normalmente? |
|---|---|---|
| **Digital** | Solo dos valores: `HIGH` (encendido) o `LOW` (apagado) | LEDs, botones, buzzers, motores simples |
| **Analógico** | Un rango de valores (en Arduino, de 0 a 1023) | Sensores de luz, potenciómetros, sensores de temperatura |

Antes de usar un pin, hay que declarar **para qué se va a usar**, dentro de `setup()`:

```cpp
const int PIN_LED = 13;      // declaramos el número de pin en una constante, para no repetirlo
const int PIN_BOTON = 2;

void setup() {
  pinMode(PIN_LED, OUTPUT);   // el pin 13 va a ENVIAR una señal (salida)
  pinMode(PIN_BOTON, INPUT);  // el pin 2 va a RECIBIR una señal (entrada)
}
```

Los pines analógicos (marcados como `A0`, `A1`, etc. en la mayoría de las placas) no necesitan `pinMode()` para leerlos, porque siempre funcionan como entrada:

```cpp
const int PIN_LDR = A0;   // declaramos el pin analógico donde está el sensor de luz

void loop() {
  int luz = analogRead(PIN_LDR);   // leemos el valor analógico directamente
}
```

En Python, la placa y la librería definen cómo se declara cada pin, pero el concepto es el mismo: primero se indica qué pin se va a usar y para qué, y después se lee o se escribe en él.

```python
from microbit import *

pin_led = pin1        # declaramos qué pin vamos a usar para el LED
pin_led.write_digital(1)   # encendemos ese pin (equivalente a HIGH)
```

## Umbral: la línea que separa "poco" de "mucho"

Un umbral es el valor que se elige como límite para tomar una decisión. No es un número fijo universal: cada docente debe definirlo según el sensor, el ambiente y el proyecto.

```cpp
const int UMBRAL = 400;   // valor a partir del cual consideramos que "está oscuro"

if (luz < UMBRAL) {
  // está oscuro
} else {
  // hay suficiente luz
}
```

### ¿Cómo se elige un umbral?

1. **Leer el sensor primero, sin ninguna lógica todavía.** Mostrar los valores en el Monitor Serial (o en pantalla) durante unos minutos, probando distintas condiciones reales (luz encendida y apagada, mano cerca y lejos del sensor de distancia, etc.).
2. **Anotar los valores típicos de cada situación.** Por ejemplo: con la luz del aula encendida, la LDR marca entre 700 y 900; con la luz apagada, marca entre 100 y 300.
3. **Elegir un número entre ambos rangos.** Un punto intermedio, como 400 o 500 en el ejemplo anterior, funciona como umbral.
4. **Probar el umbral en la situación real** y ajustarlo si el sensor reacciona demasiado pronto o demasiado tarde.

> **Nota para docentes:** no existe un umbral "correcto" en abstracto. Depende del sensor específico, de la iluminación del salón, de la superficie que refleja el sensor de distancia, etc. Enseñar a los estudiantes a **medir primero y decidir después** es más valioso que darles un número ya definido.

## Ejemplo progresivo: función con parámetro, pin, condicional y umbral

Este ejemplo combina una función con parámetro, la declaración de un pin analógico y un umbral definido después de medir:

```cpp
const int PIN_LDR = A0;      // pin analógico donde está conectado el sensor de luz
const int PIN_LED = 13;      // pin digital donde está conectado el LED
const int UMBRAL = 450;      // definido después de medir el ambiente del aula

void encenderSiOscuro(int nivelDeLuz) {
  // esta función recibe el nivel de luz como parámetro y decide qué hacer
  if (nivelDeLuz < UMBRAL) {
    digitalWrite(PIN_LED, HIGH);   // está oscuro: encendemos el LED
  } else {
    digitalWrite(PIN_LED, LOW);    // hay suficiente luz: apagamos el LED
  }
}

void setup() {
  pinMode(PIN_LED, OUTPUT);   // configuramos el LED como salida
  Serial.begin(9600);         // iniciamos el Monitor Serial para revisar los valores
}

void loop() {
  int luz = analogRead(PIN_LDR);   // leemos el sensor de luz
  Serial.println(luz);              // mostramos el valor, útil para ajustar el umbral
  encenderSiOscuro(luz);            // llamamos a la función, pasándole la lectura actual
  delay(200);
}
```

## Nota docente

Cuando un estudiante pregunte "¿cómo sé qué número poner de umbral?", la respuesta correcta casi nunca es un número: es "medí primero". Ese hábito —observar los datos antes de programar la decisión— es una de las competencias más importantes que esta progresión busca instalar, y se aplica igual de bien a un sensor de luz que a un sensor de distancia o de temperatura.
