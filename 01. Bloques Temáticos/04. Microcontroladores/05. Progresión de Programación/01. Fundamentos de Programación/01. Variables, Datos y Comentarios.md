## Descripción

Explica, desde cero, qué es una variable, qué tipos de datos se usan en programación física y cómo documentar código con comentarios, usando ejemplos aplicables a cualquier microcontrolador.

---

## Propósito

Todo programa que lee un sensor o mueve un actuador necesita guardar números en algún lado: la temperatura que se acaba de leer, la posición a la que debe ir un servomotor, el número de veces que se presionó un botón. Ese "lugar donde se guarda un número" es una variable. Sin entender qué es una variable, ninguna línea de código posterior tiene sentido.

---

## ¿Qué es una variable?

Una variable es una **caja con nombre** donde el programa guarda un valor para usarlo más adelante. En vez de escribir el mismo número muchas veces en el código, se guarda una sola vez en una variable y se usa ese nombre donde haga falta.

Piénsalo como una etiqueta pegada en una caja de guardar cosas: la etiqueta dice `temperatura`, y adentro de la caja hay un número que puede cambiar con el tiempo (por eso se llama "variable").

```cpp
int temperatura = 24;   // se crea una caja llamada "temperatura" y se guarda el número 24
```

En esa línea pasan tres cosas:
1. `int` indica **qué tipo de dato** va a guardar la caja (en este caso, un número entero).
2. `temperatura` es **el nombre** que se le da a la caja.
3. `= 24` es **el valor** que se guarda dentro, en este momento.

---

## Tipos de datos más comunes

No todas las cajas guardan el mismo tipo de contenido. Elegir el tipo correcto evita errores y hace el código más claro.

| Tipo de dato | ¿Qué guarda? | Ejemplo |
|---|---|---|
| `int` | Números enteros, sin decimales | `int cuenta = 5;` |
| `float` | Números con decimales | `float temperatura = 24.7;` |
| `bool` | Solo dos valores posibles: verdadero o falso | `bool encendido = true;` |
| `char` / `String` | Texto: una letra o una palabra completa | `String mensaje = "Hola";` |

> **Nota para docentes:** en Arduino (C++) hay que escribir el tipo de dato antes del nombre de la variable, como en los ejemplos de arriba. En Python (MicroPython, CircuitPython) esto no es necesario: se escribe directamente `temperatura = 24` y el lenguaje detecta el tipo de dato automáticamente. Es una de las diferencias más notorias entre ambos lenguajes.

```python
temperatura = 24.7   # en Python no se escribe el tipo de dato antes del nombre
encendido = True     # en Python, verdadero y falso se escriben con mayúscula inicial
```

## Variables que no cambian: constantes

A veces se necesita un valor que **nunca** va a cambiar durante todo el programa, como el número de un pin. Para esos casos se usa `const`, que le indica al programa (y a quien lea el código) que ese valor es fijo:

```cpp
const int PIN_LED = 13;   // el pin del LED nunca va a cambiar en este programa
```

Usar `const` para valores fijos y nombres en mayúsculas (`PIN_LED`, no `pinLed`) es una convención muy común en programación física: ayuda a diferenciar de un vistazo qué valores se pueden modificar durante la ejecución y cuáles no.

---

## Comentarios: documentar lo que hace cada línea

Un comentario es una línea de texto que el programa **ignora por completo** al ejecutarse. Sirve únicamente para que una persona (el mismo docente, un estudiante, u otra persona que lea el código después) entienda qué hace cada parte sin tener que descifrarlo.

En Arduino (C++), los comentarios de una línea empiezan con `//`:

```cpp
int umbral = 400;   // valor a partir del cual se considera "oscuro"
```

En Python (MicroPython, CircuitPython), los comentarios de una línea empiezan con `#`:

```python
umbral = 400   # valor a partir del cual se considera "oscuro"
```

**Todo el código de esta progresión de programación va a incluir un comentario en cada línea relevante**, siguiendo este mismo estilo. Por ejemplo, así se ve el código de un sensor de luz ya comentado línea por línea:

```cpp
const int PIN_LDR = A0;      // aquí declaramos en qué pin está conectado el sensor de luz
int luz = analogRead(PIN_LDR); // aquí llamamos al sensor de luz y guardamos lo que lee
```

> **Nota para docentes:** escribir comentarios no es opcional en esta progresión. Es la forma más rápida de que un estudiante (o un docente) entienda, meses después, por qué escribió una línea de código de cierta forma.

## Ejemplo progresivo: guardar y mostrar una lectura con nombre claro

Este ejemplo junta todo lo visto en este archivo: una constante para el pin, una variable que cambia, un tipo de dato correcto y comentarios en cada línea.

```cpp
const int PIN_LDR = A0;     // constante: el pin del sensor de luz nunca cambia en este programa
int nivelDeLuz;              // variable: va a guardar la lectura del sensor, que sí cambia

void setup() {
  Serial.begin(9600);        // iniciamos la comunicación con el Monitor Serial para poder ver los datos
}

void loop() {
  nivelDeLuz = analogRead(PIN_LDR);   // leemos el sensor de luz y guardamos el número en la variable
  Serial.println(nivelDeLuz);         // mostramos ese número en el Monitor Serial
  delay(200);                         // esperamos 200 milisegundos antes de volver a leer
}
```

La misma idea, en Python (por ejemplo, en un módulo IdeaSense o micro:bit con pines analógicos):

```python
from microbit import *

# constante: el nombre que le damos al pin no cambia durante el programa
PIN_LDR = pin0

while True:
    nivel_de_luz = PIN_LDR.read_analog()  # leemos el sensor y lo guardamos en una variable
    display.scroll(str(nivel_de_luz))     # mostramos el número en la pantalla de LEDs
    sleep(200)                            # esperamos 200 milisegundos antes de repetir
```

## Nota docente

Si un estudiante pregunta "¿por qué hay que escribir `int` antes del nombre?", una analogía útil es la de las cajas de una bodega: cada caja tiene una etiqueta que dice qué tipo de cosa guarda (herramientas, papeles, ropa), para que nadie intente meter algo que no corresponde. `int` es la etiqueta que dice "aquí solo van números enteros".
