## Descripción

Enseña a programar la IdeaBoard en sus dos entornos —IdeaScratch (bloques) e IdeaCode (texto, CircuitPython)— partiendo de cero, e integra sensores y actuadores externos usando lo aprendido en [`02. Sensores y Actuadores`](../02.%20Sensores%20y%20Actuadores/README.md).

## Entorno 1: IdeaScratch (bloques)

En [`ideascratch.crcibernetica.com`](https://ideascratch.crcibernetica.com/), el bloque `poner LED RGB en color` enciende el LED integrado. Al igual que en MakeCode, es útil comparar el bloque con su equivalente en texto para desmitificar el código.

**Motor DC integrado con bloques:** el bloque `motor A adelante a velocidad` mueve uno de los dos motores integrados de la placa.

---

## Entorno 2: IdeaCode (CircuitPython)

En [`ideacode.crcibernetica.com`](https://ideacode.crcibernetica.com/), la placa aparece como una memoria USB con un archivo `code.py` que se ejecuta automáticamente al guardar.

**LED RGB integrado:**

```python
import board
import neopixel

led = neopixel.NeoPixel(board.NEOPIXEL, 1)   # declaramos el LED RGB integrado

led.fill((0, 255, 0))   # aquí encendemos el LED en color verde
```

**Motores DC integrados**, siguiendo la misma lógica de [`04. Motor DC y Driver.md`](../02.%20Sensores%20y%20Actuadores/04.%20Motor%20DC%20y%20Driver.md) pero con la librería propia de la IdeaBoard:

```python
from ideaboard import IdeaBoard
import time

placa = IdeaBoard()   # creamos el objeto que representa toda la placa

placa.motor_a.forward(70)   # aquí llamamos al motor A y le pedimos ir hacia adelante al 70%
time.sleep(2)
placa.motor_a.stop()          # detenemos el motor
```

## Conectar sensores externos por STEMMA/QWIIC o pines generales

Los 7 pines de uso general de la IdeaBoard reciben sensores externos igual que cualquier otra placa basada en ESP32. Un sensor de luz externo, siguiendo [`01. Sensor de Luz (LDR).md`](../02.%20Sensores%20y%20Actuadores/01.%20Sensor%20de%20Luz%20%28LDR%29.md):

```python
import board
import analogio

pin_ldr = analogio.AnalogIn(board.A0)   # declaramos el pin analógico del sensor de luz
umbral = 20000   # en CircuitPython, analogio.AnalogIn lee en una escala de 0 a 65535

while True:
    luz = pin_ldr.value   # aquí llamamos al sensor de luz
    print(luz)
```

> **Nota para docentes:** cada librería de CircuitPython puede usar una escala distinta (0–1023, 0–4095, 0–65535). Siempre conviene imprimir el valor crudo primero, como se explicó en [`03. Funciones, Pines y Umbrales.md`](../01.%20Fundamentos%20de%20Programación/03.%20Funciones%2C%20Pines%20y%20Umbrales.md), antes de definir cualquier umbral.

**Servomotor** en uno de los 7 pines con alimentación directa, ideales para este actuador:

```python
import board
import pwmio
from adafruit_motor import servo

pwm = pwmio.PWMOut(board.D5, duty_cycle=2 ** 15, frequency=50)
mi_servo = servo.Servo(pwm)

mi_servo.angle = 90   # aquí movemos el servomotor a 90°
```

## ¿Cómo se carga el programa a la placa?

1. Conectar la IdeaBoard por USB-C.
2. Para bloques: abrir `ideascratch.crcibernetica.com` y hacer clic en "Ejecutar" o "Descargar".
3. Para Python: abrir `ideacode.crcibernetica.com`, editar el código y guardar. La placa lo ejecuta de inmediato.

## Ejemplo progresivo: robot simple con motor y LED de estado

Este ejemplo integra un motor integrado, el LED RGB y una función, en CircuitPython:

```python
from ideaboard import IdeaBoard
import neopixel
import board
import time

placa = IdeaBoard()                              # objeto que representa la placa completa
led = neopixel.NeoPixel(board.NEOPIXEL, 1)       # LED RGB integrado

def avanzar_y_avisar(velocidad, segundos):
    # función que mueve el motor y cambia el color del LED según el estado
    led.fill((0, 255, 0))          # verde: en movimiento
    placa.motor_a.forward(velocidad)
    time.sleep(segundos)
    placa.motor_a.stop()
    led.fill((255, 0, 0))          # rojo: detenido

avanzar_y_avisar(60, 2)   # avanzar al 60% de velocidad durante 2 segundos
```

## Nota docente

La IdeaBoard es la única placa de esta progresión con motores DC integrados en la propia placa, sin necesitar un módulo L298N externo. Eso simplifica mucho la primera experiencia con robots con ruedas: el docente puede saltar directo a programar el movimiento, sin resolver primero las conexiones del driver.
