## Descripción

MakeCode es un entorno de programación visual desarrollado por Microsoft que funciona directamente en el navegador sin instalar nada. Permite programar placas como micro:bit, Circuit Playground Express y Minecraft Education usando bloques que se arrastran y conectan visualmente.

Su característica más poderosa para la educación es el simulador integrado: antes de conectar ningún dispositivo físico, el programa se puede probar en un modelo virtual que imita el comportamiento real de la placa.

![Interfaz de MakeCode para micro:bit: área de bloques a la izquierda, simulador de la placa a la derecha](https://makecode.com/static/playground/editor.png)

---

## Acceso al editor

- micro:bit: `makecode.microbit.org`
- Circuit Playground: `makecode.adafruit.com`
- Minecraft Education: `minecraft.makecode.com`

No requiere cuenta para usar el editor. Crear cuenta permite guardar proyectos en la nube.

## Estructura del editor

**Panel izquierdo:** el simulador. Muestra un modelo virtual de la placa con LEDs, botones, sensores y todos los componentes disponibles. Cuando se hacen cambios en el programa, el simulador los refleja inmediatamente.

**Panel central:** los cajones de bloques, organizados por categorías con colores. Las categorías principales son:
- **Básico** (azul claro): mostrar texto, números e imágenes en el display de LEDs
- **Entrada** (dorado): botones, gestos, temperatura, brújula, acelerómetro
- **Música** (violeta): tonos, melodías, efectos de sonido
- **Led** (rojo): control individual de cada LED de la matriz
- **Radio** (morado oscuro): comunicación entre micro:bits por radio
- **Bucles** (verde): repetir, para siempre, para cada elemento
- **Lógica** (teal): si/entonces, comparaciones, operadores booleanos
- **Variables** (naranja): crear, leer y modificar variables
- **Matemáticas** (lila): operaciones aritméticas, aleatoriedad, redondeo
- **Avanzado**: pines, comunicación serial, funciones personalizadas

**Panel derecho:** el área de programación. Los bloques se arrastran aquí y se encajan entre sí.

## Primer programa: Mostrar texto al presionar botón A

```
al presionar botón A
    mostrar cadena "Hola"
```

En MakeCode, este programa se construye arrastrando:
1. Bloque "al presionar botón A" (de Entrada)
2. Bloque "mostrar cadena" (de Básico) dentro del anterior
3. Escribir "Hola" en el campo de texto del bloque

El simulador muestra el efecto inmediatamente sin conectar la placa.

---

## Variables y lógica: contador de presiones

```
al iniciar
    establecer [contador] en 0

al presionar botón A
    cambiar [contador] en 1
    mostrar número [contador]

al presionar botón B
    establecer [contador] en 0
    mostrar número 0
```

Este programa introduce dos conceptos fundamentales: la variable (contador) que guarda y recuerda un valor, y los eventos separados para cada botón.

## Transición a JavaScript

MakeCode tiene una vista de código en JavaScript que muestra exactamente el mismo programa en texto. Esta característica es invaluable para la transición al nivel de texto:

```javascript
input.onButtonPressed(Button.A, function () {
    contador += 1
    basic.showNumber(contador)
})
let contador = 0
```

Mostrar al estudiante el equivalente en JavaScript mientras trabaja con bloques reduce la misteriosidad del código en texto y hace que la transición sea gradual.

## Carga del programa en la placa

1. Conectar la micro:bit por USB. Aparece como unidad de disco `MICROBIT`.
2. En MakeCode, hacer clic en el botón "Descargar" (o el botón con el ícono de USB).
3. Se descarga un archivo `.hex`.
4. Arrastrar ese archivo a la unidad `MICROBIT` en el explorador de archivos.
5. La placa parpadea y ejecuta el nuevo programa.

## Proyectos de referencia en MakeCode

- Piedra-Papel-Tijera (agitar para elegir al azar) → variables, aleatoriedad, display
- Medidor de pasos (contar agitaciones del acelerómetro) → eventos, variables, condiciones
- Comunicador de mensajes (enviar texto entre dos micro:bits por radio) → radio, variables, bucles

## Notas docentes

El simulador de MakeCode es tan preciso que muchos estudiantes se sorprenden cuando el programa funciona exactamente igual en la placa que en el simulador. Es una oportunidad para hablar sobre modelos y simulaciones: el simulador es un modelo del hardware real, y por eso predice correctamente el comportamiento.

Una actividad efectiva de primer día: pedirle al grupo que programe algo específico usando solo el simulador (sin conectar la placa), lo prueben hasta que funcionen bien, y solo entonces lo carguen en la placa física. Ese orden de operaciones establece el hábito de probar en simulador antes de buscar errores en el hardware.
