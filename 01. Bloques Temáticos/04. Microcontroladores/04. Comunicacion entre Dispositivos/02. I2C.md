# I2C: Bus de Dos Cables

![Diagrama del bus I2C con maestro y múltiples esclavos conectados a SDA y SCL](https://upload.wikimedia.org/wikipedia/commons/thumb/3/3e/I2C.svg/640px-I2C.svg.png)

I2C (Inter-Integrated Circuit, pronunciado "I cuadrado C") es un protocolo de comunicación diseñado para conectar múltiples dispositivos usando solo dos cables compartidos. La elegancia de I2C está en su economía de cableado: sin importar cuántos dispositivos se conecten al bus, siempre son dos cables de señal más GND y VCC.

---

## Los dos cables: SDA y SCL

**SDA (Serial Data):** Cable por donde viajan los datos en ambas direcciones. En un momento dado, solo un dispositivo puede transmitir.

**SCL (Serial Clock):** Cable de reloj que sincroniza la transmisión. El dispositivo maestro (normalmente el microcontrolador) controla el reloj.

En Arduino UNO, los pines I2C son A4 (SDA) y A5 (SCL). En Arduino Nano son los mismos pines A4/A5. En ESP32 son GPIO 21 (SDA) y GPIO 22 (SCL) por defecto (configurable).

---

## Direcciones I2C: cómo se distinguen los dispositivos

Cada dispositivo I2C tiene una dirección única de 7 bits (128 posibles, de las cuales algunas están reservadas). Cuando el maestro quiere hablar con un dispositivo, primero envía la dirección. Solo el dispositivo con esa dirección responde.

| Dispositivo | Dirección típica |
|---|---|
| Pantalla OLED SSD1306 | 0x3C o 0x3D |
| Módulo RTC DS3231 | 0x68 |
| Acelerómetro MPU6050 | 0x68 o 0x69 |
| Expansor de pines PCF8574 | 0x20 a 0x27 |
| Sensor de temperatura MCP9808 | 0x18 |

Si dos dispositivos tienen la misma dirección y se conectan al mismo bus, colisionan y ninguno funciona. Algunos módulos permiten cambiar la dirección soldando puentes o modificando jumpers.

---

## Resistencias pull-up: obligatorias en I2C

Los buses I2C requieren resistencias de pull-up en SDA y SCL (típicamente 4.7 kΩ a 10 kΩ conectadas a VCC). Sin pull-up, las líneas pueden quedar en estados indefinidos. La mayoría de los módulos de desarrollo incluyen sus propias resistencias de pull-up en la placa, por lo que normalmente no hay que agregar resistencias externas. Si hay problemas de comunicación, verificar primero si los pull-ups están presentes.

## I2C Scanner: encontrar las direcciones de los dispositivos

Antes de usar cualquier módulo I2C, conviene escanear el bus para confirmar la dirección real con la que el módulo responde. Este sketch estándar prueba todas las direcciones y reporta las que responden:

```cpp
#include <Wire.h>

void setup() {
  Wire.begin();
  Serial.begin(9600);
  Serial.println("Escaneando bus I2C...");
}

void loop() {
  int encontrados = 0;

  for (int addr = 1; addr < 127; addr++) {
    Wire.beginTransmission(addr);
    int error = Wire.endTransmission();

    if (error == 0) {
      Serial.print("Dispositivo encontrado en 0x");
      if (addr < 16) Serial.print("0");
      Serial.println(addr, HEX);
      encontrados++;
    }
  }

  if (encontrados == 0) {
    Serial.println("No se encontraron dispositivos.");
  }

  delay(3000);
}
```

Abrir el monitor serial a 9600 bps. El scanner lista todas las direcciones que responden. Si no aparece ningún dispositivo aunque está conectado, revisar el cableado SDA/SCL y verificar que el dispositivo tiene alimentación.

## Pantalla OLED SSD1306 con librería Adafruit

La pantalla OLED SSD1306 de 128×64 píxeles es uno de los primeros módulos I2C que se trabajan en el makerspace. El texto y gráficos son claramente visibles y el módulo es robusto para el uso en clase.

**Instalar las librerías** (Gestor de Librerías del IDE):
- Adafruit SSD1306
- Adafruit GFX Library

```cpp
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>

#define ANCHO 128
#define ALTO  64

Adafruit_SSD1306 oled(ANCHO, ALTO, &Wire, -1);

void setup() {
  Serial.begin(9600);

  if (!oled.begin(SSD1306_SWITCHCAPVCC, 0x3C)) {
    Serial.println("No se encontró la pantalla OLED");
    while (true);
  }

  oled.clearDisplay();
  oled.setTextSize(2);
  oled.setTextColor(SSD1306_WHITE);
  oled.setCursor(10, 20);
  oled.println("Hola!");
  oled.display();
}

void loop() {}
```

## Mostrar datos de sensor en la OLED

```cpp
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>

Adafruit_SSD1306 oled(128, 64, &Wire, -1);

void setup() {
  oled.begin(SSD1306_SWITCHCAPVCC, 0x3C);
}

void loop() {
  int distancia = analogRead(A0) / 10;  // ejemplo simplificado

  oled.clearDisplay();
  oled.setTextSize(1);
  oled.setTextColor(SSD1306_WHITE);
  oled.setCursor(0, 0);
  oled.println("Sensor de distancia");

  oled.setTextSize(3);
  oled.setCursor(20, 25);
  oled.print(distancia);
  oled.println(" cm");

  oled.display();
  delay(200);
}
```

## Múltiples dispositivos en el mismo bus

La ventaja principal de I2C es conectar varios dispositivos con los mismos dos cables. Simplemente se conectan en paralelo (SDA de todos al pin SDA, SCL de todos al pin SCL) y cada uno responde a su propia dirección:

```cpp
#include <Wire.h>
#include <RTClib.h>                 // para el RTC DS3231
#include <Adafruit_SSD1306.h>       // para la pantalla OLED

RTC_DS3231 rtc;
Adafruit_SSD1306 oled(128, 64, &Wire, -1);

void setup() {
  Wire.begin();
  rtc.begin();         // 0x68
  oled.begin(SSD1306_SWITCHCAPVCC, 0x3C);   // 0x3C
}

void loop() {
  DateTime ahora = rtc.now();

  oled.clearDisplay();
  oled.setCursor(0, 0);
  oled.setTextSize(2);
  oled.printf("%02d:%02d:%02d", ahora.hour(), ahora.minute(), ahora.second());
  oled.display();

  delay(1000);
}
```

## I2C en MicroPython (ESP32)

```python
from machine import Pin, I2C
import ssd1306

i2c = I2C(0, scl=Pin(22), sda=Pin(21), freq=400000)

# escanear dispositivos
dispositivos = i2c.scan()
print("Dispositivos encontrados:", [hex(d) for d in dispositivos])

# pantalla OLED
oled = ssd1306.SSD1306_I2C(128, 64, i2c)
oled.fill(0)
oled.text("Hola MicroPython", 0, 0)
oled.show()
```

La librería `ssd1306.py` para MicroPython se descarga desde el repositorio oficial de MicroPython y se copia al sistema de archivos de la placa.
