Un pin digital es el punto donde el microcontrolador "toca" el mundo exterior. Por ese punto pasan señales de solo dos tipos: **encendido (HIGH)** o **apagado (LOW)**. No hay valores intermedios. El microcontrolador puede tanto producir esas señales (modo salida) como leerlas desde el exterior (modo entrada).

Entender los pines digitales es el punto de partida de cualquier proyecto de electrónica con microcontroladores.


## Propósito

Explicar el funcionamiento de los pines digitales en microcontroladores para que los docentes puedan enseñar a los estudiantes a controlar LEDs, botones y otros componentes de encendido/apagado.

---

## Configurar un pin: OUTPUT o INPUT

Antes de usar cualquier pin, hay que decirle al microcontrolador si va a producir señales o a leerlas. Esto se hace en la función `setup()`:

```cpp
void setup() {
  pinMode(13, OUTPUT);  // el pin 13 va a enviar señales → controla un LED
  pinMode(2, INPUT);    // el pin 2 va a leer señales → conectado a un botón
}
```

---

## Escribir en un pin (modo OUTPUT)

```cpp
digitalWrite(13, HIGH);  // enciende el pin (5V en Arduino, 3.3V en micro:bit/ESP32)
delay(1000);             // esperar 1 segundo
digitalWrite(13, LOW);   // apaga el pin (0V)
delay(1000);
```

Este es el programa "Blink" —el "Hola Mundo" de la programación física. Con un LED conectado al pin 13, parpadea una vez por segundo.

---

## Leer un pin (modo INPUT)

```cpp
int estadoBoton = digitalRead(2);  // devuelve HIGH (1) o LOW (0)

if (estadoBoton == HIGH) {
  digitalWrite(13, HIGH);  // botón presionado → LED encendido
} else {
  digitalWrite(13, LOW);   // botón suelto → LED apagado
}
```

## El problema del pin "flotante"

Cuando un pin está configurado como INPUT y no tiene nada conectado (o el botón está suelto), el pin queda "flotando" en el aire. Eso hace que capte interferencias eléctricas del ambiente y su lectura salte entre HIGH y LOW de forma aleatoria, aunque nadie toque nada. Se llama **pin flotante** y es la causa de muchos comportamientos raros en proyectos de principiantes.

**La solución:** resistencias de pull-up o pull-down, que mantienen el pin en un valor estable cuando no hay nada conectado.

---

## INPUT_PULLUP: la solución más sencilla

Arduino tiene resistencias de pull-up integradas que se activan con una línea de código, sin necesitar resistencias físicas adicionales:

```cpp
void setup() {
  pinMode(2, INPUT_PULLUP);  // activa resistencia interna
  pinMode(13, OUTPUT);
}

void loop() {
  if (digitalRead(2) == LOW) {  // LOW = botón presionado (lógica invertida)
    digitalWrite(13, HIGH);
  } else {
    digitalWrite(13, LOW);
  }
}
```

**¿Por qué la lógica está "al revés"?** Con pull-up, cuando el botón está suelto el pin está en HIGH (la resistencia lo mantiene arriba). Al presionar el botón, el pin cae a LOW (se conecta a tierra). Es contraintuitivo pero es el método más robusto.

---

## El rebote del botón

Cuando se presiona un botón mecánico, los contactos metálicos no se tocan de una sola vez limpia: **rebotan** varias veces en los primeros milisegundos, generando múltiples pulsos que el microcontrolador interpreta como varias pulsaciones distintas. Para una lámpara no importa mucho, pero para un contador de pulsaciones puede dar resultados incorrectos.

**Solución simple:** añadir un pequeño delay después de detectar la pulsación:

```cpp
if (digitalRead(2) == LOW) {
  // acción al presionar
  delay(50);  // esperar 50ms para que pase el rebote
}
```

## En micro:bit

La micro:bit tiene botones integrados (A y B) que se leen directamente:

```python
from microbit import *

while True:
    if button_a.is_pressed():
        display.show(Image.HAPPY)
    elif button_b.is_pressed():
        display.show(Image.SAD)
    else:
        display.clear()
```

Para un botón externo conectado a los pines P0, P1 o P2:

```python
from microbit import *

while True:
    if pin0.read_digital() == 0:   # LOW = botón presionado
        pin1.write_digital(1)       # encender LED externo
    else:
        pin1.write_digital(0)
```

## Regla de corriente: lo más importante

Cada pin de Arduino puede suministrar o absorber **máximo 40 mA**. Un LED típico necesita 10–20 mA: está dentro del límite. Un motor DC puede necesitar 200–500 mA: destruiría el pin si se conecta directo. 

Siempre que la carga necesite más corriente de la que el pin puede dar, se usa un transistor o driver como intermediario.

## Ideas de proyectos

- **Alarma con botón:** al presionar un botón, un buzzer suena y los LEDs se encienden
- **Contador de pulsaciones:** cada vez que presionas el botón, el número en pantalla sube
- **Control de motor:** un botón para cada dirección del motor
- **Luz de emergencia:** al presionar y mantener el botón, el LED parpadea rápido

## Nota docente

Los pines digitales son el primer concepto eléctrico que trabajan los estudiantes. La analogía más efectiva es la del interruptor de luz: un botón presionado es como levantar el interruptor, un pin en HIGH es la luz encendida.

Para primaria, el simulador de MakeCode (micro:bit) permite ver visualmente el estado de los pines sin necesitar el hardware físico. Para secundaria, el Monitor Serial del Arduino IDE muestra los valores leídos en tiempo real, haciendo visible lo que el programa "está viendo".
