# Pines Digitales

![Diagrama de resistencia pull-up en botón conectado a microcontrolador](https://upload.wikimedia.org/wikipedia/commons/thumb/5/5f/Switch_pull-up.png/320px-Switch_pull-up.png)

Un pin digital es el punto donde el microcontrolador toca el mundo. Por ese punto pasan voltajes de 0 V (LOW) o 3.3 V / 5 V (HIGH), y el microcontrolador los produce o los lee dependiendo de cómo se configuró el pin. Entender esta configuración es el punto de partida de cualquier proyecto de programación física.

---

## pinMode: declarar la dirección del pin

Antes de usar cualquier pin, hay que decirle al microcontrolador si va a leer o a escribir. Eso se hace con `pinMode()` en la función `setup()`:

```cpp
void setup() {
  pinMode(13, OUTPUT);  // el pin 13 va a producir señales
  pinMode(2, INPUT);    // el pin 2 va a leer señales
}
```

Si se olvida llamar a `pinMode()`, el pin queda en un estado indefinido. En Arduino los pines sin configurar se comportan como entradas de alta impedancia, lo cual produce lecturas erróneas e impredecibles.

---

## digitalWrite: producir una salida digital

Una vez configurado como OUTPUT, el pin puede ponerse en HIGH o LOW:

```cpp
void loop() {
  digitalWrite(13, HIGH);  // el pin sube a 5 V (o 3.3 V)
  delay(1000);              // esperar 1 segundo
  digitalWrite(13, LOW);   // el pin baja a 0 V
  delay(1000);
}
```

Este es el programa "Blink", el equivalente del "Hola Mundo" en programación física. Un LED conectado entre el pin 13 y GND (con resistencia de 220 Ω en serie) parpadeará una vez por segundo.

---

## digitalRead: leer una entrada digital

Un pin configurado como INPUT lee si el voltaje que llega es HIGH o LOW:

```cpp
int estadoBoton;

void loop() {
  estadoBoton = digitalRead(2);
  if (estadoBoton == HIGH) {
    digitalWrite(13, HIGH);
  } else {
    digitalWrite(13, LOW);
  }
}
```

El valor de retorno de `digitalRead()` es siempre `HIGH` (1) o `LOW` (0). No hay valores intermedios, aunque el voltaje real sea 2.3 V o 1.7 V: el microcontrolador lo clasifica según un umbral interno.

---

## El problema del pin flotante

Cuando un pin está configurado como INPUT y no hay nada conectado, el pin queda "flotante". Un pin flotante capta interferencias electromagnéticas del ambiente y su lectura puede cambiar entre HIGH y LOW de forma aleatoria, aunque no haya botón conectado. Para un botón o interruptor, esto significa que el pin reportaría pulsaciones fantasmas aunque nadie lo toque.

La solución son las resistencias de pull-up y pull-down.

---

## Resistencia pull-up

Una resistencia de pull-up conecta el pin a VCC (voltaje de alimentación) a través de una resistencia de valor alto (típicamente 10 kΩ). Cuando el botón no está presionado, la resistencia mantiene el pin en HIGH. Cuando el botón se presiona y conecta el pin a GND, el pin cae a LOW.

```
VCC (5V)
  │
 10kΩ  ← resistencia pull-up
  │
  ├──── pin 2 (INPUT)
  │
[botón]
  │
GND
```

La lógica queda invertida respecto a lo que parece intuitivo: no presionado = HIGH, presionado = LOW. Hay que tenerlo en cuenta al escribir el condicional.

---

## INPUT_PULLUP: pull-up integrado en el chip

Los microcontroladores Arduino tienen resistencias de pull-up internas que se activan con una sola línea de código, sin necesidad de componentes externos:

```cpp
void setup() {
  pinMode(2, INPUT_PULLUP);  // activa pull-up interno (~20-50 kΩ)
  pinMode(13, OUTPUT);
}

void loop() {
  if (digitalRead(2) == LOW) {  // LOW = botón presionado
    digitalWrite(13, HIGH);
  } else {
    digitalWrite(13, LOW);
  }
}
```

Esta es la forma recomendada para leer botones en Arduino. Simplifica el circuito y es más robusta que dejar el pin flotante.

---

## Efecto rebote (debounce)

Cuando se presiona un botón mecánico, los contactos metálicos no hacen contacto limpio de una sola vez: rebotan varias veces en los primeros milisegundos, produciendo múltiples pulsos rápidos que el microcontrolador interpreta como múltiples pulsaciones. Este fenómeno se llama rebote o "bounce".

Para un LED que enciende y apaga, el rebote es apenas visible. Para un contador de pulsaciones o un sistema que detecta el momento exacto de la presión, el rebote produce errores importantes.

**Solución por software (delay simple):**

```cpp
bool estadoAnterior = HIGH;
bool estadoActual;

void loop() {
  estadoActual = digitalRead(2);
  if (estadoActual == LOW && estadoAnterior == HIGH) {
    // aquí se detectó una pulsación real
    digitalWrite(13, !digitalRead(13));  // alternar LED
    delay(50);  // esperar 50 ms para que pase el rebote
  }
  estadoAnterior = estadoActual;
}
```

**Solución por software (millis, sin bloqueo):**

```cpp
unsigned long ultimoRebote = 0;
const unsigned long TIEMPO_REBOTE = 50;
bool estadoAnterior = HIGH;

void loop() {
  bool lectura = digitalRead(2);
  if (lectura != estadoAnterior) {
    if (millis() - ultimoRebote > TIEMPO_REBOTE) {
      estadoAnterior = lectura;
      if (lectura == LOW) {
        // acción al presionar botón
        digitalWrite(13, !digitalRead(13));
      }
    }
    ultimoRebote = millis();
  }
}
```

La segunda versión es más correcta para programas que deben hacer otras cosas mientras esperan el botón, porque no usa `delay()`.

---

## Corriente máxima: la regla más importante

Cada pin digital de Arduino puede suministrar o absorber un máximo de 40 mA. La suma de todos los pines no debe superar 200 mA. Superar estos límites daña el microcontrolador de forma permanente.

Un LED típico necesita 10 a 20 mA. Una resistencia de 220 Ω con 5 V limita la corriente a aproximadamente 13.6 mA: seguro para el pin. Un motor DC de 100 mA conectado directamente destruiría el pin. Siempre que la carga necesite más corriente de la que el pin puede dar, se usa un transistor o driver como intermediario.

---

## En micro:bit (MakeCode y MicroPython)

En MakeCode, los pines P0, P1 y P2 son los más accesibles. Se configuran automáticamente según el bloque que se use:

```
// MakeCode (JavaScript equivalente)
pins.digitalWritePin(DigitalPin.P0, 1)  // HIGH
pins.digitalReadPin(DigitalPin.P1)       // leer
```

En MicroPython para micro:bit:

```python
from microbit import *

while True:
    if pin2.read_digital() == 0:   # botón externo presionado (LOW)
        pin0.write_digital(1)       # LED externo encendido
    else:
        pin0.write_digital(0)
```

El micro:bit también tiene dos botones integrados (A y B) que se leen directamente con `button_a.is_pressed()` sin necesidad de configurar pines.
