# Monitor Serial

El monitor serial es la ventana al interior del microcontrolador. Cuando un programa no se comporta como se esperaba, el monitor serial permite ver exactamente qué valores está leyendo el sensor, en qué momento toma una decisión y qué valor tiene cada variable. Es el equivalente electrónico del `print()` de Python o del `console.log()` de JavaScript, y es la herramienta de depuración más usada en programación de microcontroladores.

---

## El protocolo UART

El monitor serial usa el protocolo UART (Universal Asynchronous Receiver-Transmitter) a través del mismo cable USB que se usa para cargar el programa. El Arduino convierte los datos digitales en una señal serial que el computador recibe y muestra en pantalla.

Para que funcione, ambos extremos deben usar la misma velocidad de transmisión, llamada baudrate. Si el Arduino envía a 9600 bauds pero el monitor está configurado a 115200, los datos llegan como caracteres ilegibles.

---

## Serial.begin(): inicializar la comunicación

La comunicación serial se inicializa una sola vez en `setup()`:

```cpp
void setup() {
  Serial.begin(9600);   // iniciar a 9600 bits por segundo
}
```

Las velocidades más comunes son 9600, 57600 y 115200 bps. Para proyectos simples 9600 es suficiente. Para proyectos que envían muchos datos rápido (como lecturas de sensor cada 10 ms) se prefiere 115200.

---

## Serial.print() vs Serial.println()

```cpp
Serial.print("Temperatura: ");   // imprime sin salto de línea
Serial.print(25.4);              // imprime el número
Serial.println(" C");            // imprime " C" y salta de línea

// Resultado: Temperatura: 25.4 C
```

`print()` imprime y el cursor queda en la misma línea. `println()` imprime y salta de línea (equivale a agregar `\n` al final). Para imprimir una línea completa con varias variables, se usa una combinación de `print()` y `println()`:

```cpp
int distancia = 43;
int luz = 512;

Serial.print("Distancia: ");
Serial.print(distancia);
Serial.print(" cm | Luz: ");
Serial.println(luz);

// Resultado: Distancia: 43 cm | Luz: 512
```

## Usar el monitor serial en el IDE

En Arduino IDE 2.x, el monitor serial se abre con `Ctrl+Shift+M` o desde el menú Herramientas > Monitor Serie. El selector de velocidad en la esquina inferior derecha debe coincidir con el baudrate del `Serial.begin()`.

El botón "Limpiar" borra el historial. El campo de texto en la parte superior permite enviar datos desde el computador al Arduino (comunicación bidireccional).

## Depuración por etapas

La estrategia más efectiva para depurar un programa con sensor es imprimir los valores en cada etapa del proceso:

```cpp
void loop() {
  // Etapa 1: valor crudo del sensor
  int rawLDR = analogRead(A0);
  Serial.print("Raw: ");
  Serial.print(rawLDR);

  // Etapa 2: valor convertido
  int porcentaje = map(rawLDR, 0, 1023, 0, 100);
  Serial.print(" | %: ");
  Serial.print(porcentaje);

  // Etapa 3: decisión
  if (porcentaje < 30) {
    Serial.println(" → OSCURO: LED encendido");
    digitalWrite(13, HIGH);
  } else {
    Serial.println(" → CLARO: LED apagado");
    digitalWrite(13, LOW);
  }

  delay(200);
}
```

Esta estructura de "imprimir en cada etapa" permite ver exactamente dónde está el problema: si el valor crudo es correcto pero el porcentaje no, el error está en el map(). Si el porcentaje es correcto pero la decisión no, el error está en el umbral del condicional.

## millis() para diagnosticar el tiempo

En programas que usan el patrón millis() para temporización, imprimir el tiempo ayuda a verificar que los intervalos se están cumpliendo correctamente:

```cpp
unsigned long intervalo = 500;
unsigned long ultimoTiempo = 0;
bool estadoLED = false;

void loop() {
  unsigned long ahora = millis();

  if (ahora - ultimoTiempo >= intervalo) {
    ultimoTiempo = ahora;
    estadoLED = !estadoLED;
    digitalWrite(13, estadoLED);

    Serial.print("t=");
    Serial.print(ahora);
    Serial.print(" ms | LED: ");
    Serial.println(estadoLED ? "ON" : "OFF");
  }

  // aquí puede ir más código que no bloquea
}
```

## Comunicación bidireccional: recibir comandos

El serial también permite enviar caracteres desde el computador al Arduino. Esto es útil para cambiar parámetros sin recargar el programa:

```cpp
void setup() {
  Serial.begin(9600);
  pinMode(13, OUTPUT);
  Serial.println("Enviar 'a' para encender, 'b' para apagar");
}

void loop() {
  if (Serial.available() > 0) {
    char comando = Serial.read();
    if (comando == 'a') {
      digitalWrite(13, HIGH);
      Serial.println("LED encendido");
    } else if (comando == 'b') {
      digitalWrite(13, LOW);
      Serial.println("LED apagado");
    }
  }
}
```

`Serial.available()` devuelve el número de bytes en el buffer de entrada. Si es mayor que cero, hay datos para leer. `Serial.read()` lee un byte del buffer.

## Serial Plotter: visualizar datos en el tiempo

Arduino IDE 2.x incluye el Serial Plotter (Herramientas > Serial Plotter), que grafica en tiempo real los valores numéricos que el Arduino envía por serial. Para que funcione, cada línea debe contener uno o más números separados por coma o espacio:

```cpp
void loop() {
  int sensor1 = analogRead(A0);
  int sensor2 = analogRead(A1);

  Serial.print(sensor1);
  Serial.print(",");
  Serial.println(sensor2);

  delay(50);  // ~20 muestras por segundo
}
```

El plotter es extremadamente útil para calibrar sensores (ver el rango real de valores), detectar ruido (ver la variación cuando el sensor no debería cambiar) y entender el comportamiento dinámico del sistema (cómo responde el sensor al movimiento o cambio de luz).

## Monitor serial en micro:bit (MicroPython + Thonny)

En Thonny con micro:bit, la salida de `print()` aparece en el panel inferior "Shell". No se necesita `Serial.begin()` porque MicroPython gestiona la comunicación REPL automáticamente:

```python
from microbit import *

while True:
    temperatura = temperature()
    luz = display.read_light_level()
    print("Temp:", temperatura, "°C | Luz:", luz)
    sleep(500)
```

La REPL también funciona como monitor interactivo: se puede escribir código Python mientras el programa corre y ejecutarlo directamente en la placa.

## Buenas prácticas

El monitor serial tiene un costo en tiempo de procesador: imprimir muchos datos a 9600 bps dentro de un `loop()` rápido puede hacer que el programa principal se vuelva lento. Para proyectos finales donde la velocidad importa, se elimina o comenta el código de depuración. Una práctica útil es usar una variable booleana `DEBUG` para controlar si se imprime:

```cpp
bool DEBUG = true;

void loop() {
  int valor = analogRead(A0);
  if (DEBUG) {
    Serial.println(valor);
  }
  // resto del programa
}
```

Cambiar `DEBUG = false` desactiva todas las impresiones sin tener que borrar el código de depuración.
