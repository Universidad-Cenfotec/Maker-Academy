## Descripción

Esta carpeta lleva una intención a una interacción programada. El estudiantado decide qué ocurre al iniciar, cómo responde el proyecto a una elección y qué hace cuando esa elección no estaba prevista. La creación puede ser una guía del makerspace, una historia interactiva o un juego que el grupo tenga motivos para construir.

Un bloque encajado no demuestra por sí solo que se comprendió su efecto. Por eso la carpeta propone anticipar el comportamiento, probarlo con otra persona y revisar una decisión concreta.

## Propósito

Ayudar a seleccionar eventos, secuencias, condiciones y repeticiones que sirvan al proyecto; distinguir el estado inicial de los cambios durante la ejecución; y hacer visible una mejora mediante pruebas con usuarios.

### Una secuencia posible

Empiece con **un evento y una respuesta visible**. Después agregue dos destinos, un caso no previsto y, únicamente si se necesita, una repetición. Si hay varias fallas, pruebe una rama por vez. El orden evita que un proyecto lleno de bloques esconda una condición que nunca se ejecuta.

| Nivel | Entrada razonable | Reto que amplía la comprensión |
| --- | --- | --- |
| **Preescolar** | Juego de «cuando muestro esta tarjeta, el personaje hace esto» con una persona que ejecuta. | Distinguir señal e instrucción; todavía no se exige interfaz digital. |
| **I Ciclo, 1.º–3.º** | Un evento de inicio y secuencia corta de acciones en bloques. | Comparar el orden de dos acciones. |
| **II Ciclo, 4.º–6.º** | Dos elecciones que cambian mensaje o movimiento. | Probar qué ocurre si la elección no corresponde a ninguna de las dos. |
| **III Ciclo, 7.º–9.º** | Separar evento, estado y regla; rastrear una condición. | Comparar el comportamiento con una versión de texto introductoria. |
| **Educación Diversificada, 10.º–11.º** | Usar una interfaz por bloques solo si ayuda a modelar o prototipar. | Justificar una transición hacia Python y diseñar pruebas equivalentes. |

### Elegir el entorno

Sprite Lab puede servir para una historia o personaje que responde a eventos. Una plataforma local o tarjetas de papel permiten desarrollar la misma pregunta si hay problemas de acceso. Consulte [Herramientas para el Aula](../06.%20Herramientas%20Para%20El%20Aula/00.%20README.md) antes de reservar equipos o pedir cuentas. Las plataformas no sustituyen la decisión sobre el reto y la evidencia.

Si el grupo ya entiende un evento y una decisión, la [ruta de Scratch](../06.%20Herramientas%20Para%20El%20Aula/04.%20Ruta%20Scratch%20Y%20Prueba%20De%20Usuario.md) permite abrir un proyecto inicial, predecir el efecto de un cambio y comprobarlo con otra persona. Para la transición de 7.º–9.º, siga con [Del Bloque al Texto](../05.%20Del%20Bloque%20Al%20Texto/00.%20README.md).

### Cómo decidir qué bloque enseñar

Parta de la acción que necesita la persona usuaria. Para una guía de estaciones, el evento responde **cuándo** aparece la pregunta; la condición, **qué** respuesta corresponde a la elección; la variable guarda **cuál** fue la elección durante esa ejecución. Una repetición solo aporta si permite intentar de nuevo y tiene una salida clara. Si un equipo aún no puede explicar dos respuestas distintas, posponga las variables y pruebe primero dos eventos de botón.

Reserve una prueba para cada pieza nueva. Después de agregar el evento, reinicie dos veces y compruebe que aparece la misma pregunta. Después de agregar la decisión, pruebe ambas opciones en distinto orden. Si el proyecto muestra una ruta anterior al reiniciar, discuta qué dato quedó guardado y dónde debe establecerse el estado inicial. Las tres pruebas forman una secuencia de depuración que el grupo puede repetir sin depender de la persona docente.

Un entorno sin botón de entrada libre no permite probar cualquier palabra; use las acciones que sí ofrece: no elegir, pulsar dos veces o reiniciar a mitad de la escena. La evidencia es la relación entre la acción real y la respuesta, no la cantidad de bloques visibles.

## Aplicación en Maker Academy

### Inspiración

Pida al grupo que observe una guía confusa del espacio: al seleccionar un destino, muestra siempre el mismo mensaje. ¿Qué necesitaría saber una persona visitante para llegar a otra estación? Escuche otras necesidades que el estudiantado quiera atender.

### Experimentación

Cada equipo bosqueja primero dos respuestas y construye una versión mínima. Una persona ajena al equipo elige sin recibir instrucciones orales. Quien creó observa el resultado, localiza la primera diferencia entre predicción y ejecución y ajusta una regla.

### Reflexión y evaluación formativa

Conserve un esquema o captura de la primera versión y una nota del cambio probado. La [guía de evaluación](../07.%20Evaluaci%C3%B3n/00.%20README.md) ofrece preguntas breves; importa que puedan explicar la relación entre evento, condición y resultado, incluso si el proyecto sigue incompleto.

## Nota docente

Cuando un proyecto no reacciona como se esperaba, pregunte primero cuál evento debía iniciarlo. Después compruebe el valor que lee la condición. Cambiar varios bloques a la vez hace difícil descubrir qué resolvió el problema.
